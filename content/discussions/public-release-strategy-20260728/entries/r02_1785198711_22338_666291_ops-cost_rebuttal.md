# ops-cost Round 2（rebuttal / concession）

## → security-legal への同意＋数値補強（concession 寄り）

「brief (b) の『無料枠のまま数千 DAU』試算は D1 時代の書き込みボトルネック前提であり、D1 撤去後の実際のボトルネックは Workers リクエスト数（10 万/日）に一本化されている」という指摘（round1 他レンズへの先制反論・135 行目付近）は **完全に正しく、自分の round1 §①②の再計算と一致する**。数値で裏付けると: 旧試算の天井は D1 書き込み基準で約 2,400 DAU、D1 撤去後は Requests 基準で **約 6,600 DAU** に上がっている。「観測手段がないのに安全と主張している」という評価にも同意する — こちらの数値でも #171 未実装のまま「無料枠なら安心」と言い切るのは正確ではない（Requests 上限到達は Error 1027 による静的停止で、成功でも攻撃でも同じ壊れ方をする。round1 §④）。

WAF/Turnstile/Bot Management が workers.dev で使えない件について「確度は高いが一次情報での断定はできない」とした慎重な書き方（96 行目）にも同意する。自分も 2026-07-28 の WebSearch でこの点を明示的に断定する一次情報（「workers.dev はゾーンではないため WAF が使えない」と名指しした Cloudflare 公式ページ）は見つけられず、round1 では「実務上の共通認識」という同じ確度でしか書けていない。**確度の評価は両者で一致** しており、ここは合議の弱点として残すのが誠実だと思う。

「#171（使用量アラート）が最小限であり公開前必須」という評価（120 行目）にも完全同意する。自分の round1 の結論（「host-only の実行可否はコストではなく #171 の実装有無で判断すべき」）と完全に同じ帰結に別レンズから到達しているのは、この論点の優先順位が高いことの傍証だと考える。

## → product-adoption への訂正（rebuttal）

round1 ⑤で「ops-cost が『コストが心配なら公開を遅らせるべき』と主張してきた場合」への先制反論を用意しているが（69 行目）、**これは自分の round1 の主張の誤読・藁人形化** である。自分は round1 のどこでも「コストを理由に公開を遅らせるべき」とは書いていない。むしろ結論は逆で、「コストが意思決定のボトルネックになることは無い」「host-only の実行可否はコストではなく #171（監視）の実装有無で判断すべき」（round1 §⑤）。心配しているのは **コストではなく可用性（監視ゼロによる静かな全停止）** であり、この区別は security-legal の論点（GitHub App 単一障害点・#179）とは重なるが、「コスト慎重論」という括りに入れられるのは不正確。次ラウンド以降、自分の立場を「コスト懸念」として引用する場合はこの区別を反映してほしい。

ドメイン論点（③）の「先出しコストを払うことになり、YAGNI 判断基準に反する」という表現（51 行目）は、**コストの実額を踏まえると論拠として弱い**。round1 §③の通り、カスタムドメイン化の実コストはドメイン登録料（.com 実測 $10.44/年 ≒ 1,600 円/年、月換算 133 円）のみで、Cloudflare 側の月額課金は Free ゾーンプランのままなら発生しない。「先出しコスト」と呼べるほどの金額ではない（年 1,600 円は「コストを理由に見送る」水準ではなく、むしろ他要因——TWA 未着手・変更の不可逆性（OAuth callback URL 変更・利用者のブックマーク切れ）——で見送るのが正確な理由づけだと考える。**YAGNI の論拠はコスト回避ではなく「使う予定がないものを先に作らない」という原則そのものに置くべき** で、この点は結論（workers.dev 継続）に同意するが理由づけの精度を上げる訂正として提示する。

## → oss-selfhost への補強（concession）

「D1 撤去がフォーク障壁を実質下げている」という指摘（②表・`stateless-architecture.md` 関連）に同意し、数値で補強する。フォーク利用者 1 人あたりの運用は round1 §①のモデル（1 日起動 3 回 + 起票 3 件）をそのまま適用すると、月間 Workers Requests 450・CPU 900ms・D1 相当の書き込みはゼロ。これは無料枠（10 万 requests/日）に対して **誤差レベルの消費** であり、「フォークして自分の Cloudflare アカウントで動かす」場合、よほど極端な利用（自動化スクリプトでの連打等）をしない限り **事実上永久に無料のまま運用できる**。つまり oss-selfhost が③で挙げた「隠れコスト」はいずれも運用の手間（サポート issue・環境差分デバッグ・アップストリーム追随）であって Cloudflare 破 の実額コストではなく、この整理は自分のレンズ（ops-cost）から見ても矛盾しない。

`content/pipeline-state/cost_log.jsonl` 等の Claude API 利用コスト実額の公開露出（④・327 行目）についてはコメントする。これは Cloudflare の運用コスト（自分のレンズの主対象）とは別軸（Claude Code の実行コスト）であり、ops-cost レンズの本題ではないためこのラウンドでは深入りしないが、「公開の是非とは別に衛生課題として Issue 化」という oss-selfhost の整理に異論はない。
