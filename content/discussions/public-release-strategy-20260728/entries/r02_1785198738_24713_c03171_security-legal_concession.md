## security-legal round 2 — concession（明示的な譲歩）

1. **ドメイン方針の理由付けを撤回・差し替え**: round 1 で「カスタムドメイン化は無料枠のまま数千 DAU の規模では過剰投資（コスト面のハードル）」と述べたが、ops-cost の実測（③・2026-07-28 WebSearch/WebFetch 確認）により誤りと判明。実費用はドメイン登録料のみ（.com 換算で年 $10.44 ≒ 1,600 円）で、WAF Free Managed Ruleset・Rate Limiting 1 ルール・Turnstile（月間 100 万 solve まで無料）はいずれも **Free ゾーンプランの範囲で使える**。「コストが高いから見送る」は撤回する。**workers.dev 継続という結論自体は維持するが、根拠を「切替の不可逆コスト」と「Free tier の Rate Limiting が 1 ルールのみで 2 エンドポイントを守り切れない（防御効果が部分的）」に差し替える**（詳細は rebuttal post）。

2. **セルフホストの「責任分散」主張に条件を追加**: round 1 で「セルフホストで法務・セキュリティ責任が利用者ごとに分散する」と述べたが、oss-selfhost の実測（fork 0・star 0）により、**この分散は理論上の可能性であって、現時点では行使されていない** ことを認める。加えて oss-selfhost ③・product-adoption ⑤が独立に指摘した「GitHub App 名称の衝突によるレピュテーションリスクの跳ね返り」「本家より低品質な設定の乱立」は、**オーナーの法的・トークン中継責任は消えても、オーナーへの評判・信頼毀損リスクは完全には消えない** ことを示す一次情報であり、round 1 の主張に以下の限定を追加する: 「セルフホストは "運営者が他人の GitHub トークンを預かる法的立場" を消すが、"運営者のブランドに帰属する評判リスク" は README での免責・命名ガイドライン（oss-selfhost ⑤-4 の提案）なしには消えない」。

3. **product-adoption の「技術的公開は既に完了・論点は集客のみ」への部分同意**: round 1 で「公開してよいか: Yes」とした自分の結論と、product-adoption の整理は実質合流していることを認める。ただし #171（NFR-14 MUST 未達）を「公開可否とは別レイヤーの運用ガード」と位置づける読み方には同意しない（rebuttal 参照）。
