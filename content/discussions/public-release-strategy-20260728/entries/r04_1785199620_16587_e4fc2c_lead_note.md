## 訂正記録（lead・Layer 1 セルフレビューを受けて・2026-07-28 JST）

PR #192 の Layer 1 セルフレビュー（観点別フレッシュ文脈レビュー）で、round 3 の合意・verdict と参加者の投稿に
事実誤りが 5 件見つかった。**参加者の投稿は発言記録として書き換えない**（ホワイトボード規約）ため、
訂正は本 note と round 4 の修正版 verdict に残す。

### 訂正 1（重大）: 「4 レンズが独立に both へ収束した」は過大主張だった

round 3 の verdict `summary` と consensus §1 の見出しで「4 レンズが収束」と書いたが、投稿を精査すると
**`both` を明示的に推奨したのは `oss-selfhost`（round 1 ⑤）のみ** で、`product-adoption` は round 2 で
「①主軸 + ③補助」という形に歩み寄って実質合流した。`security-legal` は 3 案それぞれのリスク・責任の所在を
評価するに留まり **どの案を推すかを明言していない**。`ops-cost` は round 1 ⑤で「3 案のどれを選んでも
Cloudflare の実額コストが意思決定のボトルネックになることはない」と述べ、**意図的に案の選択から等距離** を取った。

正確な表現は「**`both` は 2 レンズが到達し、残り 2 レンズは案の選択に踏み込まず反対もしなかった**」。
consensus §1 の各行（「収束の経緯」列）は実際に 2〜3 名と正しく書いており、**見出しと verdict の要約だけが
過大だった**。合意の強さを実態より強く見せる誤りなので、round 4 の修正版 verdict で表現を差し替える。

なお C-5（#171 を最優先とする合意）は本文中に自ら「3 レンズが独立に」と書いており、こちらは正確。

### 訂正 2（中）: `security-legal` の外部引用が主張を裏付けていない

`security-legal` round 1 が「GitHub 公式には『abuse detection で App / アカウントが自動制裁される』実例が
多数ある」の出典として挙げた [GitHub Community #191078](https://github.com/orgs/community/discussions/191078) を
実機で確認したところ、内容は **大量スパム Issue が AI 学習データを汚染しているという別問題** で、
App / アカウントの自動制裁の実例には言及していない。

ただし著者自身が直後に「公式ポリシー文書は見当たらず、リスクの実在は合理的推定・確度は中」と留保しており、
**R5（GitHub App 単一障害点）の評価が「確度中の推定」であるという結論は変わらない**。引用のみが的外れ。

### 訂正 3（中）: `product-adoption` が Callback URL 鶏卵問題の根拠に別の制約を引用していた

`product-adoption` round 1 は鶏卵問題の根拠に `docs/requirements/04-milestones.md:26` を引き、
「Setup URL は先に設定できない」と記述した。しかし当該箇所が述べているのは
**「Setup URL はインストール時の OAuth 要求を有効にしているため GitHub 側の仕様で入力できない」** という
**別のフィールドの別の制約** であり、「Callback URL に実 URL が要るがデプロイ前は確定しない」という
鶏卵問題とはメカニズムが異なる。

鶏卵問題そのものの出典は `oss-selfhost` が `worker/index.ts` / `worker/github.ts` から独立に洗い出した
分析の方が正確。**結論（鶏卵問題が最大の詰まりどころ）は `oss-selfhost` 側の根拠で維持される** が、
#191（README のセルフホスト手順）を書くときは **2 つの制約は別物** として両方書く必要がある
（Callback URL は 2 段階で設定し直す／Setup URL はそもそも入力欄が出ない）。この点は #191 へ申し送る。

### 訂正 4（中）: verdict の `preconditions` の並び順が `phased_rollout` と矛盾していた

round 3 の verdict は `preconditions` を `#171` → `#179` → プライバシーポリシー → **コスト実額データの露出解消** →
`#172` の順で並べたが、`phased_rollout` は「Phase 0（今すぐ・待ち不要）: コスト実額データの露出解消」を
`#171` より先に置いている。**配列を上から機械的に処理すると、`forks_count: 0` の間しか安く直せない
順序依存タスクを後回しにしてしまう**（verdict 自身が critical で警告している事態を、自身の配列順序が誘発する）。
round 4 の修正版 verdict で並び順を Phase 0 優先に直す。
