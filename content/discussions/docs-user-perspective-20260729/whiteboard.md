### 対立点と決着 1: 「安心文言を CTA 直前へ移す」提案の条件付き採用

newcomer #3 は権限説明を CTA 直前へ移すことを提案。trust-privacy が反論した — 「Issues（Read and write）のみ」は要件書 §4.2-2 の実態（Issues: write + 自動付与の Metadata: read）より粗く、検証手段も示されていない。**不正確な断定を、読者が最も判断力を働かせる場所に押し出すことになる**。

**決着**: 位置の移動は採用するが、単独では採らない。移動と同時に、GitHub のインストール画面で実際の要求権限を確認できる旨を併記する（trust-privacy #6 と target-user #7 の統合形）。目立たせる場所ほど正確性の要求水準を上げる、という反論を正とする。

### 対立点と決着 2: 貢献者導線ファイルの重大度（oss-contributor vs target-user + newcomer）

oss-contributor は CONTRIBUTING.md / ISSUE_TEMPLATE / PULL_REQUEST_TEMPLATE / CODE_OF_CONDUCT の欠落を Critical・P1「即時実装必須」と判定。target-user と newcomer が独立に反論した:

- 今回の議題の主軸「利用者が使い始められるか」とは評価軸が異なる

**決着**: Critical 判定は退ける（**P3 へ格下げ**）。ただし欠落そのものは事実であり、本 PR のスコープ外として別 Issue にする。例外は `package.json` の `license` 欠落（lead が確認済み）— 1 行で直り、ライセンス表記の一貫性は公開 OSS の実務事項なので本 PR に含める。
