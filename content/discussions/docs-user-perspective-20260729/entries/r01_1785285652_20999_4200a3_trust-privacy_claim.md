## trust-privacy レンズ: README の信頼判断材料としての検証結果（重要度順 8 件）

### 1. README がプライバシーポリシー・利用規約への導線を一切持たない
- **該当箇所**: README.md 全体（`/privacy` `/terms` へのリンクが皆無。`grep` で確認済み）
- **問題**: トークンの最長有効期限（30 日）・ログアウトと GitHub 側失効の違い・削除範囲・問い合わせ窓口（GitHub Issues）は `src/i18n/translations.ts` の `privacy` セクション（アプリ内 `/privacy`）にしか書かれていない。README から辿る手段がない。
- **信頼判断への影響**: 「サーバーはデータを保存しません」を読んで安心した直後、その裏付け・失効手順・問い合わせ先を確認する動線が断たれる。書き込み権限を渡す前に規約を読む、という最低限の導線が欠けている。
- **推奨修正**: README にプライバシーポリシー・利用規約への Markdown リンクを追加する（フッターや「できること」節の近辺）。

### 2. README が名指しする「データ保持インベントリ」自体が、既に解消済みの不一致を未解決として記載している
- **該当箇所**: `docs/research/2026-07-28-data-retention-inventory.md` §9「見つかった差分」1 番（アカウント削除がプライバシーポリシーの「送信履歴」削除記載より狭いと結論）
- **問題**: 実装（`src/auth/AccountDeletion.tsx` → `clearAllLocalUserData()`、`src/auth/useAuthState.ts` のコメントに `#181` 明記）は既に `draft` / `offlineQueue` / `sentRequestIds` まで削除するよう修正済み。ドキュメントは「不一致あり」のまま更新されていない。
- **信頼判断への影響**: README がこの文書を「どのデータがどこに保持されるかの全数棚卸し」として名指しで信頼の根拠に挙げているのに、その文書自体が実装とズレた古い結論を残している。慎重な読者が裏取りのつもりで開くと、逆に「プライバシーポリシーは実装と食い違っている」という誤った不信を持ちかねない。
- **推奨修正**: `data-retention-inventory.md` §9 の差分 1 番を「#181 で解消済み」に更新する。

### 3. 「サーバーはあなたのデータを保存しません」が無条件の断定で、実際の限定（基盤ログ）を伝えていない
- **該当箇所**: README.md L11「サーバーはあなたのデータを保存しません。〜（データベースを持っていません）」
- **問題**: `stateless-architecture.md` §8・プライバシーポリシー §5 は「Cloudflare 基盤側に例外ログが 5% サンプリング・最長 3 日残りうる」ことを明記し、`public-release-risk-cost.md` は「『ログは一切取っていません』とは言えない」「ポリシー文面はこの粒度に合わせるのが正確」と自ら釘を刺している。README の一文にはこの限定が無く、証拠のない安心文言になっている。
- **信頼判断への影響**: 詳細ドキュメントまで読み進めた読者は「README の断定は正確ではなかった」と感じる。過剰な安心文言はそれ自体がリスク。
- **推奨修正**: README に「（Cloudflare 基盤の例外ログのみ最長 3 日残る場合があります）」等の一言注記を足すか、データ保持インベントリへのリンクを断定文の直後に置く。

### 4. トークンの失効・取り消し手順が README から読み取れない
- **該当箇所**: README.md L11（トークンの Cookie 保存の説明のみ）
- **問題**: (a) 最長 30 日の絶対期限、(b) ログアウトだけでは GitHub 側トークンは失効せずアカウント削除時のみ失効 API を呼ぶこと（`stateless-architecture.md` §4）、(c) 利用者自身が GitHub の Authorized/Installed Apps 画面から取り消す手段、のいずれも README に無い。
- **信頼判断への影響**: 書き込み権限を渡す前に読み手が最も知りたい「渡した権限をどう取り消せるか」に README だけでは答えられない。
- **推奨修正**: 「できること」または新設の「安全性」節に、失効手段（GitHub 側の連携解除 + アプリ内アカウント削除）を 1〜2 行で明記する。

### 5. 運営主体・ホスティング先の開示が README に無い
- **該当箇所**: README.md 全体（「個人開発の OSS」は SECURITY.md のみに記載）
- **問題**: 誰が運営しているか、ホスティング先が Cloudflare（米国法人）でデータセンターが国外にもまたがりうることは、プライバシーポリシー §2 にしかない。README には無い。
- **信頼判断への影響**: 自分の GitHub アカウントへの書き込み権限を渡す判断材料として、運営主体・ホスティング先は README の時点で開示すべき最低限の事実。
- **推奨修正**: README 冒頭かフッターに「個人開発の OSS（Cloudflare Workers 上で運用）」の一言を追加する。

### 6. 「コードには一切アクセスしません」がリポジトリのソースからは検証不能
- **該当箇所**: README.md L32「要求する権限は Issues（Read and write）のみ。コードには一切アクセスしません」
- **問題**: GitHub App の要求権限は GitHub 側の App 設定（リポジトリ外）で決まり、本リポジトリのコード（`worker/`）からは確認できない。README はこの主張を検証する手段（GitHub のインストール確認画面で実際の要求権限を見られる、という導線）を示していない。
- **信頼判断への影響**: 断定のみで裏取り経路が無いため、慎重な読み手が自分で真偽を確かめられない。
- **推奨修正**: 「GitHub のインストール画面で要求権限をご確認いただけます」等、検証手段への言及を添える。

### 7. 障害時・サービス終了時の告知方針が README に無い
- **該当箇所**: README.md 全体
- **問題**: `public-release-risk-cost.md` R10 は「障害に気づく手段がない（監視・オンコールなし）」と明記し、利用規約には「サービス変更/終了の可能性」の記載があるとされるが、README にはこの点への言及が一切ない。
- **信頼判断への影響**: 個人 OSS 規模で過大な運用体制までは不要だが、「落ちても通知は来ない・止まる可能性がある」という最低限の期待値調整は README にあってよい。
- **推奨修正**: 「個人開発のため可用性は保証しません」程度の一文を SECURITY.md か README に追加する。

### 8. セルフホストの可否が README に一切書かれていない
- **該当箇所**: README.md 全体
- **問題**: MIT ライセンスでコードは公開されているが、自分のインフラで動かせるか（GitHub App の Client ID/Secret を自分で発行する前提が要るか等）への言及が無い。
- **信頼判断への影響**: 「運営者を信頼できないなら自前でホストする」という代替選択肢の有無が不明。
- **推奨修正**: 開発節か README 末尾に「セルフホスト可否」を一言追記する（現状は未対応でも、その旨を明記するだけで十分）。
