# レンズ: 実利用者（Android で GitHub Issues を日常運用）視点 — README だけで「ログイン→ショートカット作成→初回起票」に到達できるか

対象を実読した上で、**初回体験を止める欠落** に絞って重要度順に指摘する。

## 1. [最重要] 目玉機能「ホーム画面にいくつでも並べられる」が実装上は成立せず、README・要件書ともに未修正のまま矛盾している

- **該当箇所**: `README.md` L33-34「ショートカット起動 — `/new?repo=...` でリポジトリ・ラベル・タイトルを初期選択した状態で開けます。**ホーム画面にいくつでも並べられます**」
- **実装の事実**: `src/i18n/translations.ts` L299-303（`shortcuts.placementGuideNote`）に、アプリ自身がこう警告している。「この URL を単体でホーム画面のアイコンにしても、初期選択（プリセット）は反映されません（アプリはトップ画面で起動します・Android の仕様）。プリセット付きで開くには上記の方法を使ってください」＝実際にプリセット付きで開けるのは **アプリ内の「保存済みショートカット」一覧からのタップのみ** で、Android ホーム画面へ直接アイコンとして置いても機能しない。
- **ドキュメントの desync**: `docs/requirements/00-requirements.md` OQ-1「クエリパラメータ付き『ホーム画面に追加』ショートカットのタップ時挙動の実機検証」は依然「M2 着手時」の **未決事項** として残っているが、コードは既に否定的な結論（standalone アイコンでは動かない）を前提に警告文まで実装済み。要件書側の更新漏れ。
- **実利用者への影響**: README を読んで「よく使うリポジトリ×ラベルをホーム画面に何個でも置ける」を差別化点として期待した初見ユーザーが、実際に URL をホーム画面へ追加すると（README にはその方法自体書かれていないので手探りで試すと）プリセットが効かず素のトップ画面が開き、「壊れている」と誤解して離脱しうる。まさに初回体験を止める欠落。
- **推奨修正**: README のこの一文に「（保存済みショートカット一覧からの起動が必要。URL 単体をホーム画面アイコンにするとプリセットは効きません）」等の注記を追加するか、bullet 自体を実態に合わせて書き換える。OQ-1 は実装済みの結論（否定的）で更新しクローズする。

## 2. PWA を「ホーム画面に追加」する具体的操作手順が README・アプリ内のどこにも無い

- **該当箇所**: README L38「PWA インストール導線からホーム画面へ追加」（できることの一項目として言及されるのみ）
- **確認事実**: `src` 配下を `beforeinstallprompt` / 「ホーム画面に追加」/ install banner 関連で検索したが、GitHub App のインストール案内（`install.title` 等・L206-211）はあるものの、**ブラウザの PWA インストール（Chrome の「アプリをインストール」）を案内する UI・文言は存在しない**。README にも「アドレスバーのアイコンをタップ」等の具体手順は無く、「👉 アプリを開く」リンクとブラウザの標準機能任せになっている。
- **実利用者への影響**: Android Chrome の PWA インストール導線は機種・Chrome バージョンで見え方が揺れるため（メニュー内「アプリをインストール」/ アドレスバーのインストールアイコン等）、"README だけを頼りに" 進める初見ユーザーはこのステップで迷う可能性がある。
- **推奨修正**: README に「Chrome でアプリを開き、メニュー（⋮）→『アプリをインストール』、またはアドレスバーのインストールアイコンをタップ」等、具体的な一文を追記する。

## 3. Organization リポジトリの「承認待ちになりうる」ことが README に一切書かれていない

- **該当箇所**: 実装済みの警告文 `src/i18n/translations.ts` L210-211（`install.orgNotice`）「Organization のリポジトリでは、管理者でない場合はインストール申請となり承認をお待ちいただくことがあります」。要件書側も FR-4 / A2-1 / リスク表（L318）で明記済み。
- **問題**: README にはこの制約の記載が無い。README の「なぜ作ったか」「できること」いずれにも Organization という語自体が登場しない。
- **実利用者への影響**: Organization 配下のリポジトリへ起票したくて試した初見ユーザーが、ログイン後の「App インストール」ステップで突然「承認待ち」に遭遇し、ミッション KPI の「初回セットアップ 5 分以内」が崩れる。README で事前に知っていれば個人リポジトリで試す等の回避判断ができたはず。
- **推奨修正**: README の「できること」または「なぜ作ったか」近辺に一文「Organization リポジトリは管理者でない場合、インストール承認待ちになることがあります」を追加。

## 4. ログインは実際には「認可（OAuth）」と「対象リポジトリへの GitHub App インストール」の 2 ステップだが、README は 1 ステップのように書いている

- **該当箇所**: README L9「PAT の発行も管理も不要 — GitHub でログインするだけ」/ L32「GitHub ログインだけで使える」
- **実装・要件の事実**: `docs/requirements/00-requirements.md` §4.2-6 / FR-4 / A2-1 の通り、ログイン（OAuth 認可）後に別途「起票したいリポジトリへの GitHub App インストール」画面での操作が必須（`install` 画面が実装済み）。
- **実利用者への影響**: 「ログインするだけ」という README の表現を字義通り信じると、ログイン直後にリポジトリが一覧に出ず戸惑う（実際には install ステップを踏む必要がある）。致命的ではないが、README のシナリオ B-1（初回セットアップ）記述（`docs/requirements/03-user-story-map.md` A2-1）と揃っていない。
- **推奨修正**: README に「ログイン → 起票したいリポジトリへ GitHub App をインストール（初回のみ）」の 2 ステップである旨を一文添える。

## 5. オフライン再送・二重起票防止の実際の限界が README では隠れて「絶対安全」に読める

- **該当箇所**: README L38「オフラインでも書ける — 圏外での起票はキューに保存され、次にアプリのホーム画面を開いたときに自動で再送されます（**二重起票はしません**）」
- **実装・要件の事実**:
  - 再送対象は **ネットワーク失敗のみ**（4xx/5xx は対象外・要件 §7.2）。
  - キューは **24 時間で失効** し、自動再送は打ち切られ、`queueExpired` として手動の再送/破棄が必要になる（`translations.ts` L257-258・D2-1）。
  - 「サーバーには届いたがレスポンスが端末に届かなかった」ケースは判別不能で **稀に重複しうることを P3 で受容** している（要件 §7.1「冪等性キーなし → タイムアウト再送で重複起票リスク」の対応方針）。
- **実利用者への影響**: README の「二重起票はしません」という言い切りは、実装が明示的に「稀に重複しうる」と認めている点と食い違う。長期間圏外だった場合に何もせず放置すると 24h で自動再送が止まる点も README には書かれておらず、「勝手に届くはず」と誤解して手動対応（D2-1 の再送/破棄）に気づかない恐れがある。
- **推奨修正**: 「（ネットワーク接続の問題のみが対象。24 時間を超えると自動再送は止まり、アプリ内の一覧から手動対応が必要です。ごく稀に重複作成される可能性があります）」等、限界を一言足す。

## 6. 利用規約・プライバシーポリシーへの導線が README に一切ない

- **該当箇所**: README「ドキュメント」節（L89-93）。要件・ミッション・リサーチへのリンクはあるが、`terms` / `privacy`（PR-1・PR-2 で必須と定義されている法務ページ）へのリンクが無い。
- **実利用者への影響**: 「信頼できるか分からないサービスに GitHub の権限を渡したくない」という公開ユーザー像（`03-user-story-map.md` ペルソナ B）を README が想定しているにもかかわらず、README だけを読む初見ユーザーは、データの扱い（サーバー保持ゼロである点等）を確認する導線に README からたどり着けない。
- **推奨修正**: README に利用規約・プライバシーポリシーへのリンクを 1 行追加する（既にアプリ内には実装済み・`account.confirmMessage` 等参照）。

## 7. [軽微] 要求権限の説明が README では不完全

- **該当箇所**: README L32「要求する権限は Issues（Read and write）のみ」。
- **実装・要件の事実**: 要件書 §4.2-2 は「Issues: write（**+ 自動付与の Metadata: read**）のみ」と明記。GitHub の認可画面には Metadata: read も表示されるはずで、README の記載と実際に画面で見るものが完全には一致しない。
- **実利用者への影響**: 軽微。「権限付与の範囲」を一字一句確認したいユーザーには小さな不一致として映る程度。
- **推奨修正**: README を「Issues（Read and write）のみ（GitHub 側で自動付与される Metadata: read を除く）」等に精緻化。
